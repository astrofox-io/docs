description: Astrofox のオーディオ、メディア、プラグイン、ディスプレイ、書き出しに関するよくある問題を解決します。
---

## ビジュアルがオーディオに反応しない

1. オーディオファイルまたはライブ入力が接続され、アクティブになっていることを確認します。
2. ファイルがソースの場合は再生を押し、ライブ入力の場合は選択した入力を開始します。
3. 組み込みのスペクトラムディスプレイで、Astrofox がオーディオを受信していることを確認します。
4. リアクターを開き、出力メーターが動いていることを確認します。
5. シグナルが弱すぎる場合は、スペクトラムの選択範囲を広げるか、**Max dB** を下げます。
6. 対象のコントロールが意図したリアクターにバインドされていて、値の範囲が平坦になっていないことを確認します。

動きが遅れる場合は、リアクターの smoothing を下げます。動きが細かく揺れすぎる場合は、smoothing を上げます。スペクトラムモードでは、decay を大きくすると下降もゆっくりになります。

## マイクや MIDI デバイスが見つからない

- ブラウザーから求められたら、マイクまたは MIDI の許可を与えます。
- デバイスが接続され、ほかのアプリケーションから使用できることを確認します。
- 新しいデバイスを接続したあとは、使用可能な入力の一覧を更新します。
- ほかのアプリがデバイスを占有している場合は、そのアプリを閉じます。
- macOS のデスクトップアプリでは、システム設定で Astrofox の許可を確認します。

デスクトップオーディオを使用できるかどうかは、選択した画面共有のソースとオペレーティングシステムによって異なります。ブラウザーによっては、タブのオーディオは取得できてもシステム全体のオーディオは取得できない場合があります。

## プロジェクトを開くとメディアが見つからない

ローカルの画像ファイルや動画ファイルは、特にプロジェクトを別のコンピューターに移したあとなど、自動的に開き直せないことがあります。**Relink Media** を使って、未解決のレイヤーごとに対応する画像や動画を選択してください。

オーディオはプロジェクトファイルに保存されません。プロジェクトを開いたあと、**Load audio** でトラックを再度読み込んでください。

作業をアーカイブしたり転送したりするときは、メディアをプロジェクトファイルと同じ場所に置いておきましょう。

## プラグインのレイヤーがレンダリングされない

1. アクションレールで **Manage plugins** を選択し、必要なプラグインがインストールされていることを確認します。
2. 開発中のプラグインの場合は、ファイルを変更したあとに再読み込みします。
3. マニフェストと参照されているファイルにアクセスでき、CORS を有効にして配信されていることを確認します。
4. 公開するプラグインには HTTPS を使用します。HTTP は localhost でのみ許可されます。
5. ブラウザーの開発者コンソールで、シェーダーのコンパイルエラーや worker のエラーを確認します。
6. アニメーションには、実時間のタイマーではなく `frame.time` を使っていることを確認します。

プレビューのフレームのレンダリングに約 3 秒以上、書き出し中に約 5 秒以上かかる worker は、Astrofox のほかの部分が動作を続けられるよう、停止されて応答なしとしてマークされます。

## Save video が開始されない

**Save video** を選択すると、必ず書き出しダイアログが開きます。確定ボタンは、書き出しが次の条件を満たすまで無効のままです。

- 5 秒以上の長さのオーディオファイル
- 終了時間より前の開始時間
- 5 秒以上の選択範囲
- プラットフォームが事前に保存先を選べる場合は、その保存先

ライブ入力だけでは、オフラインで書き出すためのタイムラインは定義されません。Save Video ダイアログでオーディオファイルを選択してください。

## 書き出しの形式が想定と異なる

Web での書き出しには、現在のブラウザーの `MediaRecorder` が対応している形式が使われます。特定の MP4 または WebM エンコーダーが必要な場合は、ffmpeg を同梱したデスクトップアプリを使用してください。デスクトップアプリが ffmpeg を見つけられない場合は、ブラウザー互換の方法にフォールバックします。

## デスクトップアプリでオーディオをキャプチャできない

マイク入力にはマイクの許可が必要です。デスクトップオーディオでは、画面収録の許可と、実際にオーディオトラックを含むキャプチャソースも必要になる場合があります。オペレーティングシステムの許可を変更したあとは、Astrofox を再起動してください。

## 古いプロジェクトの要素が失われた

Astrofox は、サポートされている 1.x のプロジェクト要素を自動的に移行します。サポートされていない要素や変換できない要素は削除され、プロジェクトを開いたときに報告されます。元の `.afx` ファイルのバックアップを保管しておき、対応付けられる要素については [1.x からのアップグレード](/docs/ja/upgrading-from-v1)を参照してください。

## バグを報告する

[Astrofox の issue トラッカー](https://github.com/astrofox-io/astrofox/issues)で既存の issue を検索するか、新しい issue を作成してください。Astrofox のバージョン、Web またはデスクトップのプラットフォーム、オペレーティングシステムとブラウザー、再現手順、共有しても問題ない場合は最小限のプロジェクトを添えてください。
